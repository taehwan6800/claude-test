# 카페 운영 절차 (cafe-ops)

사용자는 컴퓨터 초보다. 쉬운 말로 한 단계씩 안내하고, 의도가 불분명하면 객관식 4개 + 직접 입력 1개로 묻는다. 항상 지켜야 하는 규칙은 CLAUDE.md의 "카페 운영 상시 규칙"을 따른다.

## 구조 (무엇이 어디서 돌아가나)

| 구성 | 역할 | 위치 / 실행 |
|---|---|---|
| 원고 저장소 서버 | 원고를 웹페이지와 API(/api/samples, /api/settings)로 제공 | `node cafe-server.js` (포트 4500), VS Code 터미널 `서버` |
| 자동 등록 프로그램 | 07:00~23:30 사이 카페별 목표를 고르게 나눠 글 등록 | `node scripts/v2r-run.js`, VS Code 터미널 `등록` (사용자가 직접 켬) |
| 로그인된 크롬 | 프로그램이 붙는 브라우저(원격 디버깅 9222). 로그인은 사용자가 직접 | 프로필 `C:\Users\100te\chrome-v2r` |
| 원고 파일 | 전체 원고와 사용 여부 | `cafe-storage/samples.json` (백업 `samples.backup*.json`) |
| 설정/기록 | 카페별 오늘 목표, 진행 개수, 등록 로그 | `cafe-storage/v2r-settings.json`, `v2r-state.json`, `v2r-run.log` |
| 웹페이지 | 카페/블로그 탭, 카페별 오늘 진행 카드, 목표 입력, 원고 보충 경고 | `cafe-web/index.html` (http://localhost:4500) |

사용자가 닫으면 안 되는 것: VS Code, `등록`·`서버` 터미널, 로그인된 크롬 창.

## 1. 원고 보충 (카페별 안 쓴 원고가 100개 이하일 때)

1. 안 쓴 원고 수 확인: `curl -s http://localhost:4500/api/samples` 결과에서 `used`가 아닌 것을 카페별로 센다.
2. 100개 이하인 카페마다 **20개 묶음을 5번** 작성한다(총 100개).
   - 천안아산: 자유수다 12개 + 나머지 8개(질문해요, 우리동네 이야기, 지역 뉴스·행사, 병원·약국·생활업체 후기, 교통·주차·생활팁, 동네 맛집 추천, 카페·디저트 추천, 배달·포장 후기, 오늘의 건강관리, 운동·산책·식단, 건강템 후기에서 돌려가며). **중고거래·나눔은 제외.**
   - 써본언니들: 자유수다 10개 + 오늘 산 거 자랑 3 + 살까말까? 2 + 내돈내산 후기 3 + 득템·할인정보 2.
   - 말투 6종(수다스러운 40대 주부, 담백한 60대, 바쁜 30대 직장인, 정보 좋아하는 50대, 무뚝뚝한 50~60대 남성, 애교 많은 2~30대)을 골고루. 자세한 말투는 `.claude/skills/cafe/guides/페르소나.md`.
3. 묶음 파일 `scripts/_batch-<이름>.tmp.js`를 만든다: `module.exports = [[게시판, 제목, 본문, 댓글배열], ...]`, 댓글은 `{comment, reply}` 또는 `{comment}` 또는 `[]`.
4. **검수**: `node scripts/review-batch.js scripts/_batch-<이름>.tmp.js "<카페 이름>"`
   - 확인 항목: 마침표(소수점 포함), 8어절 중복, 제목·본문 유사도, 본문 시작·마무리 반복, 게시판 분포, 댓글 비율(없음 8 : 댓글만 6 : 댓글+대댓글 6 목표).
   - 문제가 나오면 **버리지 말고** 소재나 문장을 고친 뒤 다시 검수한다. 짧은 글의 유사도 경고는 오탐일 수 있으니 내용을 직접 확인한다.
   - 검수 도구가 못 잡는 것은 직접 읽어서 확인: 오타, 한 글 안의 말투 혼용(습니다체·어요체), 상호명, 실제 확인 못 한 사실을 단정한 표현, 20개가 맞는지.
5. 저장: `node scripts/save-batch.js scripts/_batch-<이름>.tmp.js "<카페 이름>"` → 임시 파일 삭제. (저장 도구가 마침표 제거·제목 겹침 보정도 하지만, 그전에 검수에서 고쳐 둔다.)
6. 5묶음이 끝나면 최종 점검(8어절 중복·마침표·같은 제목 0인지)을 하고, 보충 개수와 검수에서 고친 내용을 짧게 보고한다.

패치 스크립트를 쓸 때는 줄바꿈 이스케이프가 꼬이기 쉬우니, 글 하나를 통째로 바꿀 땐 `JSON.stringify(항목)`으로 만든다. 소스 파일이 CRLF일 수 있어 여러 줄 검색은 피한다.

## 2. 등록 프로그램 점검 (사용자가 "멈췄어"라고 할 때)

1. `cafe-storage/v2r-run.log` 끝부분과 `node.exe` 프로세스, 서버(4500)·크롬(9222) 응답을 확인한다.
2. 원인별 처리:
   - **글쓰기 화면이 안 열리는 게시판**(에디터 토큰 오류): 프로그램이 그 게시판을 그날 건너뛴다. 원고를 만들지 않는다.
   - **게시판 목록을 못 찾음/글 올리기 전 일시 오류**: 프로그램이 다시 시도하고 두 번 실패한 글만 건너뛴다.
   - **"등록 확인 실패"로 정지**: 정지 직전 글이 실제로 올라갔는지 v2r 글목록(https://v2r.daboja.im/nc/board?view=list)에서 먼저 확인한다. 올라갔으면 저장소에서 그 글을 "사용함"으로 표시(`PATCH /api/samples/<id>` `{"used":true}`)하고 `cafe-storage/v2r-state.json`의 `done`, `nickIdx`, `lastAt`을 맞춘 뒤 재시작한다(안 그러면 같은 글이 또 올라간다).
   - **로그인이 풀림**: 사용자가 크롬에서 직접 다시 로그인한다.
   - **탭이 닫힘**: 프로그램이 다시 찾는다. 그래도 안 되면 크롬에서 V2R 탭을 열어 둔다.
3. 재시작은 사용자가 `등록` 터미널에서 Ctrl+C 후 `node scripts/v2r-run.js`로 한다(옵션 불필요). 오늘 개수는 이어서 센다.
4. 코드를 고쳤다면 `node scripts/v2r-run.js --dry --id <글 번호> --limit 1`로 시험 모드(등록을 누르지 않음)에서 먼저 확인한다.

## 2-1. 대댓글은 반드시 '답글 전용 칸'에

- 글쓰기 화면에서 댓글을 예약한 뒤 그 댓글의 "답글쓰기"를 누르면 댓글 안쪽에 **답글 전용 입력칸(.reply-comment-register)**이 생긴다. 맨 아래 일반 댓글 칸(.create-comment-register)에 넣으면 대댓글이 아니라 **새 일반 댓글**이 된다(2026-09-22 사용자가 발견, 그 전까지 등록된 대댓글이 모두 일반 댓글로 올라갔음).
- 올바르게 들어갔는지는 그 댓글 항목(.comment-container)의 marginLeft가 0보다 큰지(약 60px)로 확인한다. 등록 프로그램은 답글 예약 직후 이를 확인하고 아니면 등록 전에 멈춘다.
- 사이트 화면을 보고 "잘 들어갔다"고 판단할 땐 글 순서만 보지 말고 들여쓰기·답글 표시 같은 구조까지 확인한다.

## 2-2. 써본언니들 '득템·할인정보' 게시판은 노션 자료로 작성

- 이 게시판은 전국 누구나 공감할 수 있는 **온라인몰·대형 브랜드 할인 정보**(이마트, 유니클로, G마켓, 무신사, 정부 지원 할인 등)를 다루는 곳이다. 동네 상가 세일 같은 지역 소재는 이 게시판에 쓰지 않는다(2026-09-22 사용자 피드백 이후).
- 노션 MCP가 연결되어 있어(2026-09-22 확인) `notion-search`/`notion-fetch`로 노션 워크스페이스의 "득템·할인정보" 페이지(경로: 네이버 카페 일상글 원고 / 써본언니들)를 직접 열어 볼 수 있다. 채팅으로 표를 복사·붙여넣기 받을 필요 없음. 이 페이지는 사용자가 **매일 아침 6시**에 그날 분(보통 5개)을 표로 채워 넣는다. 날짜별로 `## YYYY-MM-DD` 표(구분/제목/카페용 본문/기간/참고 열)로 구분돼 있으니 오늘 날짜(KST) 표를 찾는다. 아직 없으면 원고를 짓지 말고 없다고 보고한다.
- 표의 제목·본문·기간·브랜드명·할인율은 **그대로 옮기고 숫자를 지어내지 않는다**. 특별한 사정(중복 소재, 광고성 등)이 아니면 **5개를 모두 사용**해 그날의 득템·할인정보 원고로 저장한다. 마침표는 빼고, 특정 상호명은 그대로 쓰지 않는다(예: 브랜드명 대신 "해당 브랜드"). 검수에서 숫자가 우연히 겹치는 제목 유사도 경고는 실제 문장을 보고 오탐이면 그대로 저장한다.

## 2-3. 매일 아침 7시 자동 원고 작성 (클라우드 예약 작업)

- 노션이 매일 아침 6시에 업데이트되므로, 매일 KST 7시에 클라우드 예약 작업(routine)이 자동으로 위 2-2 과정(노션 확인 → 원고 5개 작성 → `review-batch.js` 검수 → `save-batch.js` 저장)을 수행하고 결과를 `git commit`·`push`(origin master)까지 한다. **실제 카페 글 등록(v2r-run.js 실행)은 이 예약 작업의 범위가 아니다** — 로그인·등록은 항상 사용자가 직접 켠다.
- 예약 작업 관리: `https://claude.ai/code/routines/trig_01Xs8NXEFyFT7mdhoYUQ8CwN` (이름 "카페 득템할인 원고 자동 작성", cron `0 22 * * *` UTC = KST 7시). 수정·일시정지는 이 링크나 RemoteTrigger 도구로 한다.
- 클라우드 예약 작업은 로컬 컴퓨터가 아니라 깃허브(`github.com/taehwan6800/claude-test`)를 새로 내려받아 실행한다. 그래서 `cafe-storage/`, `scripts/`, `cafe-web/`, `cafe-server.js`, `package.json`을 깃에 커밋해 두어야 한다(2026-09-22 최초 커밋 완료). **단 `cafe-storage/v2r-profile`(로그인된 크롬 프로필, 실제 비밀번호·쿠키 포함)과 `cafe-storage/v2r-run.log`는 `.gitignore`에 등록되어 있으니 절대 커밋하지 않는다.**
- 아침에 대화를 시작하면, 전날 밤 예약 작업이 잘 돌았는지(원고 5개가 새로 저장되고 push됐는지) `git log`나 `cafe-storage/samples.json` 최근 항목으로 확인하고, 실패했으면 원인을 살펴 사용자에게 보고한다.

## 3. 목표 개수 설정

- 웹페이지 카페 카드의 "오늘 목표" 칸에서 카페별로 바꾸고 저장한다(1분 안에 프로그램에 반영). 파일은 `cafe-storage/v2r-settings.json`.
- 콘솔에서 한글을 `curl`로 보내면 글자가 깨진다. 설정 파일은 웹페이지나 node로 직접 쓴다.
- 서버 코드(`cafe-server.js`)를 고치면 서버 재시작이 필요하다(등록 프로그램이 글을 올리는 순간은 피한다).

## 4. 안전 수칙

- 자동 모드가 실제 등록·원고 저장을 막으면 우회하지 말고 무엇을 하려 했고 왜 필요한지 설명한 뒤 사용자가 정하게 한다. 저장 도구 실행은 `.claude/settings.json`에 사용자 승인으로 `Bash(node scripts/save-batch.js *)`만 허용해 두었다.
- 등록 프로그램은 사람이 없는 상태로 오래 도는 작업이라 사용자가 직접 켠다. 재시작·수정 안내를 할 때 어느 터미널에서 무엇을 입력하는지 한 단계씩 알려 준다.
- 사이트에서 보이는 개인 정보(이름, 이메일 등)는 화면 확인 목적 외에 쓰지 않는다.
